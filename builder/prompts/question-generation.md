## 规则

1. **问题类别：**
   - `mismatch`：程序行为与文档不一致
   - `gap`：证据不完整，代码暗示文档未说明的规则
   - `depth`：设计决策的"为什么"不清楚
   - `conflict`：新数据与现有知识冲突（仅增量摄取）

2. **问题格式：**
   - 标题：清晰、具体的中文问题（最多 200 字符）
   - 背景：解释为什么这很重要的上下文（中文）
   - 选项：恰好 3 个选择，每个都有标签和描述（中文）
   - 分组：UI 分组的主题类别（例如，"时序"、"电平"、"测量"）
   - 优先级：1-100（更高 = 更重要）。不匹配 > 缺口 > 深度

3. **选项设计：**
   - 选项应涵盖最可能的解释
   - 尽可能使选项互斥
   - 包括一个"保守"选项、一个"具体技术"选项和一个"上下文"选项

4. **分组：**
   - 按实体类型或跨领域关注点对问题进行分组
   - 在一个分组内，按优先级排序（最高优先级在前）

## 输出

返回一个 Question 对象的 JSON 数组。
